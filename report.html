PROJECT REPORT · COMPILER DESIGN

MiniLang Studio

Mini Compiler for a Simple Programming Language
Interactive compiler phases, a custom language, and a step-by-step virtual machine

Prepared as an educational implementation for Systems Programming and Compiler Design.

Abstract

MiniLang Studio is an educational compiler project that makes compilation observable. It implements a custom language named MiniLang and displays each stage from editable source code through lexical analysis, parsing, AST construction, symbol-table creation, semantic analysis, intermediate-code generation, target-code generation, virtual-machine execution, and output. The application is local, self-contained, and uses a handwritten compiler so that each major decision stays inspectable.

Objectives

  • Demonstrate the standard compiler flow in one working system.
  • Define an original language with syntax and semantic rules.
  • Generate real tokens, trees, symbols, instructions, and output for user programs.
  • Report positioned lexical, syntax, semantic, and runtime errors.
  • Execute generated instructions one at a time with visible state changes.

Requirements and technology

The project runs in a modern browser with no installation, account, external library, server, database, or network requirement. HTML, CSS, and vanilla JavaScript implement the interface and compiler. Node.js is only needed to run the automated tests.

MiniLang language definition

Tokens

Keywords are begin, end, let, int, real, bool, text, when, otherwise, show, true, and false. Identifiers start with a letter or underscore. Comments use //. Strings use double quotes and support newline, tab, quote, and backslash escapes.

Grammar (EBNF)

program = "begin" { statement } "end" EOF ; statement = declaration | assignment | conditional | output ; declaration = "let" identifier ":" type "=" expression ";" ; assignment = identifier "=" expression ";" ; conditional = "when" "(" expression ")" block [ "otherwise" block ] ; block = "{" { statement } "}" ; output = "show" "(" expression ")" ";" ; type = "int" | "real" | "bool" | "text" ; expression = or ; or = and { "||" and } ; and = equality { "&&" equality } ; equality = comparison { ("==" | "!=") comparison } ; comparison = addition { ("<" | "<=" | ">" | ">=") addition } ; addition = product { ("+" | "-") product } ; product = unary { ("*" | "/" | "%") unary } ; unary = ("!" | "-" | "+") unary | primary ; primary = literal | identifier | "(" expression ")" ;

Semantic rules

MiniLang supplies int, real, bool, and text. Arithmetic requires numeric values; division returns real; remainder requires integers. Text values concatenate with +. Conditions and logical operators require bool. An integer can widen to real; narrowing is rejected. Every block has lexical scope. Names must be declared before use, and duplicate active names or shadowing are errors.

Architecture

Source Program ↓ Lexical Analysis → token table and scanner trace ↓ Syntax Analysis → parser trace ↓ Abstract Syntax Tree ↓ Symbol Table ↓ Semantic Analysis → typed AST and diagnostics ↓ Intermediate Code → three-address code ↓ Target Code → register instructions ↓ Execution → VM state and history ↓ Output

Compiler phases

PhaseImplementation and visible result
Lexical analysisMaximal-munch scanner creates tokens with lexeme, category, decoded value, line/column, and trace.
Syntax analysisRecursive-descent parser applies grammar and records tokens consumed.
ASTSource-spanned Program, declaration, assignment, conditional, output, expression, and literal nodes.
Symbol table / semanticsScope stack creates unique IDs, resolves names, infers types, checks compatibility, and records diagnostics.
Intermediate codeThree-address code uses temporaries, labels, explicit casts, jumps, and prints.
Target codeRegister-machine instructions load, store, calculate, compare, branch, print, and halt.
ExecutionVM displays PC, registers, symbol-ID memory, output, and before/after changes for every instruction.

Worked example

begin let count : int = 5; let price : real = 12.5; let total : real = count * price; show(total); end

The symbol table creates s0 for count:int, s1 for price:real, and s2 for total:real. Code generation makes an explicit integer-to-real conversion before multiplication:

s0 = 5 s1 = 12.5 t0 = s0 t1 = real(t0) t2 = t1 * s1 s2 = t2 print s2 halt

The generated target program prints 62.5. Each load, store, conversion, multiplication, print, and halt appears in the Execution view.

Errors, limits, and verification

Every error includes its phase, message, line, and column. Earlier phase artifacts stay visible after a later failure. Runtime failures preserve prior output and instruction history. Limits are 50,000 source characters, 128 nesting levels, 20,000 trace events per phase, 50,000 VM instructions, and 1,000,000 output-string characters.

The automated test run uses node --test tests/compiler.test.cjs. Result: 58 passing tests, 0 failures. It covers lexical positions and escapes, grammar, scopes, types, conversion, code provenance, branches, short-circuiting, VM output/state, errors, limits, reset, and equivalence of Run versus Step Instruction.

Limitations and future scope

The first version excludes loops, functions, input, arrays, optimization, and implicit conversions other than integer-to-real. Future work can add these language constructs, a control-flow graph, optimization passes, breakpoints, file import/export, and guided exercises.

Conclusion

MiniLang Studio integrates core compiler-design concepts in a working system. Its custom grammar, handwritten compiler, generated target instructions, position-aware diagnostics, and visual virtual machine make the full path from source program to output accessible for study and demonstration.
